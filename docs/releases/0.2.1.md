# FloatingX-Harmony 0.2.1

修复 ArkUI 手势事件 fingerList 中的空槽引发的 TypeError。Android 行为基准仍为 FloatingX 2.3.7；本版不改变主指选择、任一轴 touchSlop 判断、接管首帧、移动坐标或抬指复位规则。

## 修复范围

仅在 FxScopePlatform 的 canStartPan、handlePan 中保护缺失的 fingerList，并在读取 finger.id 前跳过 undefined 元素。有效触点仍按原主指 ID 匹配；不自动换指，不修改业务、布局或跨平台框架。

[官方手势接口](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/ts-gesture-common/)说明：先按下但未参与当前手势的手指，在 fingerList 对应位置为空。Android 使用 MotionEvent 读取指针，不存在此 ArkUI 数组空槽访问路径。保留 fingerList 可避免为此 patch 引入 API 20 的 fingerInfos 依赖。

## 验证

- 新增 7 项宿主测试，覆盖横纵方向的连续数组、稀疏数组、显式 undefined、列表缺失、主指缺失及后续有效事件恢复。原源码在新增用例中失败 5 项；修复后全部 300 项核心测试和 12 项发布工具测试通过。
- 本机核心构建使用 `npm run build:core -- --typeRoots ./node_modules/@types` 隔离父目录 Node 类型，再运行 `node --test tests/*.test.mjs`；不修改库的类型或工程配置。
- DevEco Studio 26.0.0.461 / HarmonyOS SDK 26.0.0.23 Beta1，release 模式 HAR 与 Demo HAP 构建通过。HAR 的 28 个源码文件及 Index.ets 与发布源码一致；真机签名包包含未签名包全部相同条目，另有本地运行元数据。
- 2026-11-12，Mate 80 Pro Max / HarmonyOS 7.0.0 API 26：维护者按清单实际触屏操作并反馈基本符合预期，结合 Demo 进程日志核对单指横纵拖动、双指移动与两种抬指顺序、浮窗外先落指后由非零 ID 触点拖动、隐藏取消及恢复后的拖动和子按钮点击。本轮采集日志未出现 TypeError。
- 日志证据：seq=1/2 为单指拖动；seq=5/6/8 无父 RELEASE；seq=7/9/10 的两次 RELEASE 坐标一致；seq=12 以 pointer=1 拖动并释放；seq=13 隐藏时收到 cancel；seq=15/16 恢复后正常释放，seq=17 收到 child click。公开仓库不包含设备标识或原始日志。

设备日志没有直接输出 fingerList 数组，不能把这些操作视为逐帧空槽形态的证明；空槽输入的失败与修复由直接调用生产实现的宿主用例验证。此次没有 Android 同机对照、Pad 或消费应用业务验收；也不将 0.2.0 的历史测试算作本版新增验证。

## 已知限制与接入

[0.2.0 已知限制](0.2.0.md#已知限制)继续适用，包括已成功子手势的即时 CANCEL、更多多指组合、Pad/多 Stage、系统窗口及 CMP 渲染边界。本版没有新增这些能力。

下载 v0.2.1 Release 的 floatingx-v0.2.1.har，核对 SHA256SUMS 后替换本地 HAR 引用。公开示例为未签名 HAP；真机需使用自己的签名。版本、源码提交、SDK、构建模式和附件哈希见 manifest.json。消费应用仍需自行同步依赖、编译并回归。
